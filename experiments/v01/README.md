# GPU-native OS prototype v0.1

CPUしか使えない環境で、独立した仮想GPUの命令セットと、その上で起動する小さなOSを検証する試作。
既存GPUのバイナリ互換性や実GPUの性能を再現するものではない。

## 実行

Python 3.10以上、外部ライブラリ不要。ZIPを展開し、このディレクトリで実行する。

```sh
python vgpu.py
python vgpu.py --self-test
python vgpu.py --waves 16 --lanes 32 --roots 1024 --seed 7 --issue random
```

- `vgpu.py`: 命令解釈、仮想wave、ベクトルレジスタ、共有RAM、原子操作、命令発行、事後検証。
- `gpu_os.asm`: ゲストOS。起動・初期タスク生成・分散スケジューリング・依存タスク生成・終了。
- `demo.json`, `self_test.json`, `stress.json`: コンテナでの実行結果。

## 仮想ハードウェア

全waveが同じROMの先頭から起動し、独立したPC・スカラレジスタ・ベクトルレジスタを持つ。
1 wave は複数laneのベクトル演算を行う。分岐はwave単位であり、lane単位の分岐・マスクは未実装。
RAMは単語アドレス指定。初期値はゼロ。整数はPythonの任意精度整数で、固定幅オーバーフローは未モデル化。
原子操作と共有メモリは逐次一貫性を仮定する。メモリレイテンシやキャッシュ、実際の同時実行はモデル化しない。
命令発行はround（各waveを1命令ずつランダム順で進める）とrandom（稼働中のwaveからランダムに1つ選択する）の2方式。
これはハードウェア側の命令発行モデルであり、ゲスト側のタスク選択は行わない。

## ゲストの共有メモリ

| ワードアドレス | 意味 |
| --- | --- |
| 0 | BOOT: 初期化公開フラグ |
| 1 | HEAD: 次に取得するキューチケット |
| 2 | TAIL: 次に確保するキューチケット |
| 3 | LIVE: 未完了タスク数（公開前の子も含む） |
| 16以降 | 1件3ワードのキュー（種類、ID、公開フラグ） |
| キュー後 | 中間結果、最終結果、root/child別の実行回数 |

root数はデバイス入力。wave 0がrootタスクを生成し、全waveが同じ分散スケジューラを実行する。
rootタスクはlaneごとの整数の二乗を計算し、wave内で加算集約する。
中間結果を保存してからLIVEを増加し、TAILで子タスクのスロットを確保し、記述子を書いて最後に公開フラグを立てる。
消費側はHEADをCASで更新し、公開フラグを確認してから記述子を読む。子タスクは中間結果を3倍し、そのroot IDを加えて最終結果を保存する。
親・子はそれぞれ完了時にLIVEを減らす。キューが空でLIVEが0なら、そのwaveはHALTする。

## 検証条件と結果

コンテナ: x86_64, Intel Xeon Platinum 8370C, 5論理CPUが可視, Python 3.13.5。
CPU上の逐次インタプリタで実行。実GPUのデバイスノードは確認されなかった。

- 4 wave × 8 lane、root 16件: 合計32タスク、全waveが8件完了、9項目すべて合格。
- wave数1/2/4/8/16、lane数1/3/8/32、root数0/1/7/32、seed 0/1/2、命令発行2方式の組み合わせ480件が全て合格。
- 命令予算超過、RAM範囲外アクセスの異常検出テストも合格。
- 16 wave × 32 lane、root 1024件、seed 7、random発行: 合計2048タスク、全結果一致、重複・欠落なし、全wave終了。

ホスト側の参照計算と検証は全waveが終了した後のみ実行する。ホストは初期ROM、デバイス入力、RAM、命令発行を提供するが、ゲストのタスクを個別に作成・選択・完了させない。

## 限界

- CPUエミュレータを別途実装したわけではない。実CPU上に仮想GPUを実装した。QEMUなどの外部エミュレータは不要。
- カスタムISAの機能シミュレーションであり、CUDA/PTX/RDNA等の実機互換性、電源投入からの物理起動、実GPU上の動作は未検証。
- OSの全機能はない。有限の非循環キュー、協調実行、信頼できる固定タスクのみ。独立したプロセスの隔離、仮想メモリ、プリエンプション、割り込み、デバイスI/O、ファイルシステム、例外からの復旧は未実装。
- 仮想機械のアドレス範囲検査は、プロセス間メモリ保護ではない。
- スケジューラの命令実行順を有限回検証した結果であり、すべての実行順・実GPUの弱いメモリ順序での正しさの完全証明ではない。
- 命令数とlane操作数はシミュレーションの計数値で、実機のクロックサイクル、並列性能、速度、電力の測定ではない。
